# Web and mobile feature parity

Audit compares the current `frontend/src` implementation with `mobile/` and the backend routes/controllers. `partial` means a core flow exists but web coverage or behavior is incomplete.

| Feature | Web file | Mobile status (done, partial, missing) | Backend endpoint | Notes |
|---|---|---|---|---|
| Reactions | `components/ChatContainer.jsx`, `components/GroupChatContainer.jsx`, `store/useChatStore.js`, `store/useGroupStore.js` | partial | `PUT /api/messages/react/:id` | Mobile group chat offers reaction selection and renders counts. DM does not expose reactions. The shared backend controller supports group messages as well. |
| Reply | `components/ChatContainer.jsx`, `components/GroupChatContainer.jsx`, `components/MessageInput.jsx`, `components/GroupMessageInput.jsx` | done | `POST /api/messages/send/:id`; `POST /api/groups/:id/messages` | DM and group message long-press can set a reply target; composers send `replyToId`, and `MessageBubble` renders the quote. |
| Forward | `components/ForwardModal.jsx`, `store/useChatStore.js` | missing | No dedicated endpoint; forward can reuse `POST /api/messages/send/:id` | Web has a recipient picker and forwards supported content. Mobile has no forward action or target picker. |
| Edit | `components/ChatContainer.jsx`, `components/GroupChatContainer.jsx`, `store/useChatStore.js`, `store/useGroupStore.js` | partial | `PUT /api/messages/edit/:id` | Mobile group messages can be edited from long-press actions. Mobile DM has no edit action. Backend edit supports group messages too. |
| Delete | `components/ChatContainer.jsx`, `components/GroupChatContainer.jsx`, `store/useChatStore.js`, `store/useGroupStore.js` | partial | `DELETE /api/messages/delete/:id` | Mobile group messages can be deleted for everyone from long-press actions. Web-push behavior and full foreground/background notification presentation parity are not implemented in the mobile client. |

## Recommended build order

1. Complete core message actions on DM and group chats: DM reactions, edit/delete, and forwarding; add a clear message action sheet.
2. Add view-once media and link previews, then message search and a complete disappearing-message experience.
3. Add block/report actions and finish public profile sharing and profile-detail parity.
4. Complete group/channel parity, including invite management and the remaining channel-specific UI; align typing and system-message behavior.
5. Finish sticker management/recents and ensure GIF search configuration is available in release builds.
6. Implement voice and video calling with the existing signaling events.
7. Finish push lifecycle parity across foreground, background, and app-launch notification handling, then re-check Settings and presence consistency.
